# A reversible layout trial on real irradiance records

**Question.** Many sensor archives need to preserve the exact original, including spaces, quality flags, sentinel values and line endings. Does placing the same byte positions from successive fixed-width records together improve complete-file compression?

**Lock before comparison.** One Bondville SURFRAD station-day, 2020 day 115, was inspected to identify its two-line prefix and fixed-width rows. The evaluation set is Fort Peck and Desert Rock, on 2020 days 032, 183 and 310. These dates span seasons without using irradiance values to select conditions. The six held-out units are separate station-days from two stations. Correlation within stations and common formatting preclude a generalization claim about all sensors. Include every selected file, with the fallback if its row width varies.

**Arms.** Compress each original with gzip level 6, bzip2 level 9, XZ preset 6, single-threaded zstd levels 3 and 19, and Brotli quality 11. For each, also compress its exact column-transposed bytes. Put the prefix and protected row delimiters through the ordinary compressor. Include a self-describing 13-byte wrapper with magic/version, backend ID, prefix size, row width and row count. The raw control uses the stock frame with no extra wrapper. Restore the complete file for every arm. Some stock streams already include their own integrity checks; use independent SHA-256 over the complete restoration in every arm.

**Decisions.** A complete-file saving over the same backend identifies the layout's incremental contribution. Also compare the smallest stock and smallest modified outputs per file, reporting the cost of offline exhaustive selection separately from a fixed default. Record exact totals. No cache, timing, energy, optical precision or field-identifiability claim follows from this byte test. Source files remain upstream. NOAA files contain observations of the real atmosphere, including missing or flagged values.

For the transferable fixed choice, select the smallest transposed method on the single development file and freeze it before interpreting held-out sizes. Report (a) that fixed method against the best native method picked independently for each held-out file and (b) the same backend with and without transpose. The source download and identical-file checks happen outside any timing claim. Run the CPU-bound commands serially with low priority.
